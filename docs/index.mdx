## Use this order

1. Read [Overview](overview.md) for the product posture and public app model.
2. Follow [Install and Prerequisites](install-and-prerequisites.md).
3. Build [Your First App](first-app.md).
4. Run the [Starter Examples](examples.md) in order.
5. Open [Showcase](showcase.md) when you want product-shaped proof.
6. Use the concept pages for the details that usually go missing in alpha docs:
   - [App Model](app-model.md)
   - [Screen and Layout Composition](layout-and-screen-composition.md)
   - [Runtime and Screen Options](runtime-and-screen-options.md)
   - [Architectural Review](architectural-review.md)
   - [Widgets Overview](controls-overview.md)
   - [Recipes Overview](recipes.md)

## What Tessera is good at

- form-heavy and workflow-heavy terminal apps
- dashboards, telemetry panels, and operational surfaces
- multi-pane workspaces and investigation shells
- semantic theming and control-level styling without inventing a second framework story
- starting small without throwing away the same public model later

## Choose the right lane

- Evaluating Tessera for a product:
  Follow [Getting Started](getting-started.md), then [Showcase](showcase.md), then [Architectural Review](architectural-review.md).
- Building an app right now:
  Start with [Install and Prerequisites](install-and-prerequisites.md), [Your First App](first-app.md), and [Recipes Overview](recipes.md).
- Looking for exact type names:
  Jump to [API Reference](api-reference.mdx) and [Public API Inventory](public-api-inventory.md).
- Hitting friction:
  Use [Troubleshooting](troubleshooting.md) and [FAQ](faq.md).
